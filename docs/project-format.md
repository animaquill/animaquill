# 项目格式

版本 1。这份说明和 [JSON Schema](../packages/schema/json-schema/) 都是公开的，其他工具和 AI 工具可以直接读写项目。完整的示例在 [packages/schema/fixtures/v1](../packages/schema/fixtures/v1/)。

## 目录结构

项目是一个普通文件夹。有 `animaquill.json` 的文件夹就是项目。

```
animaquill.json                    项目信息：语言、画幅、时间轴、字体、标签
assets.json                        项目用到的所有素材文件
libraries.json                     关联的素材库和经验库
libraries.lock.json                每个库固定的存档
notes.json                         批注
timelines/<id>/timeline.json       时间轴的母版
timelines/<id>/overrides/          语言和画幅的差异
scenes/<id>/scene.json             场景：真实的 HTML、CSS、SVG 和 JavaScript
sounds/<id>/sound.json             声音：用代码生成的音效和音乐
music/<id>.json                    音符形式的音乐，格式待定
code/                              场景和声音共用的代码
locales/<语言>.json                字符串表
assets/                            素材文件
.animaquill/                       本机内容，不进 Git
```

其他文件编辑器不管，也不会改动，比如 `AGENTS.md`、`README.md` 和制作笔记。

`.animaquill/` 里是编辑器在这台电脑上用的东西：`recovered/` 是编辑器盖掉一个文件之前存下的原文件；`proxies/` 是代理文件，比项目大或帧率高的视频在这里有一份小一些的 H.264 预览版，只给预览用，导出始终用原片，删掉会重新生成。

## 通用规则

**规范写法。** 同样的内容总是写成同样的文本：字段顺序固定，映射按键排序，片段按时间排序，小对象写在一行。所以保存不会改动没变的内容，Git 差异只显示真实的改动。

**严格校验。** 文件里出现未定义的字段、写错的属性名或不可能的值，这个文件就不能进入项目，错误里写明位置。这样手写或 AI 写的错误能马上发现。

**ID。** 所有对象都有稳定的 ID，只能用英文字母、数字、下划线和连字符。时间轴、场景和声音的 ID 就是文件夹名，不符合规则的文件夹算错误。同一类对象的 ID 不能重复。

**时间。** 单位是秒，写成字符串，这样是精确值。能在九位小数内精确表示时写小数，否则写分数：

```json
{ "start": "12.5", "duration": "1001/30000" }
```

帧率同样写成字符串，比如 `"30"` 或 `"30000/1001"`。

**位置和大小。** 用世界单位，原点在画面中心，见[世界坐标](#世界坐标)。比例只留给相对于自己的量：锚点和裁切。

**路径和地址。** 路径是项目内的相对路径，不能用 `..`。网络地址只能用 https。

**插件。** 内置名称不带点。插件提供的内容类型、效果和转场带点，比如 `plugin.lottie`。没有安装插件时内容原样保留。

## animaquill.json

```json
{
  "formatVersion": 1,
  "id": "atoms-demo",
  "name": "原子是什么",
  "languages": [{ "id": "zh-CN", "name": "中文" }, { "id": "en", "name": "English" }],
  "formats": [{ "id": "landscape", "name": "横屏", "width": 1920, "height": 1080, "fps": "30" }],
  "timelines": ["main"]
}
```

`languages` 和 `formats` 的第一项是母版。`timelines` 的第一项默认打开。此外还有 `description`、`fonts`、`tags`、`cover` 和 `credits`。

带 `locked` 的标签表示项目不可编辑，用户和 AI 都不能改，直到标签被移除。

## 时间轴

```json
{
  "name": "主线",
  "sections": [{ "id": "section_intro", "name": "片头", "duration": "5" }],
  "markers": [{ "id": "marker_hook", "time": "0.342", "name": "钩子", "note": "第一句话抓住观众" }],
  "tracks": []
}
```

时间轴的长度是所有段落时长的和，没有单独的字段。段落的时长可以按语言变化，后面的段落自动后移，所以至少要有一个段落。

`beatGrid` 是节拍线，`mix` 是总线和主输出。

### 轨道

`kind` 是 `video`、`audio` 或 `caption`。第一条轨道在画面最下层。

音频轨道可以写 `role`（`voice`、`music`、`effects`）、`properties`、`effects`、`sends` 和 `output`。片段在音频轨道上可以重叠，声音会混在一起。在其他轨道上重叠会列入问题。

视频和音频轨道可以写 `joins`，是两个片段之间的衔接转场，见[转场](#转场)。

`locked: true` 锁定轨道，只是方便人在编辑器里操作：时间轴上这条轨道的片段和转场不能拖动、修剪、切割、删除或改属性，框选和全选不选它们，轨道也不能删除。AI、在编辑器外面改的文件和其他命令都不受锁定限制，`locked` 本身谁都能改。

### 片段

```json
{
  "id": "clip_title",
  "name": "标题",
  "start": "0",
  "duration": "5",
  "source": { "kind": "scene", "scene": "title" },
  "properties": { "opacity": 1 }
}
```

`start` 是母版时间轴上的时刻。时间都是精确值，不依赖帧率。

项目的 `fps` 是剪辑帧率：标尺按它计数，拖动的落点在它的帧上，不写时用第一个画幅的帧率。每个画幅的 `fps` 是导出帧率，可以和项目不同，导出时按时间取样。

片段有自己的时钟：第一帧时读数是 `offset`（默认 0），之后和时间轴同速走。关键帧和字幕里每个词的时间都是这个时钟的读数，所以移动、裁剪和切割片段都不用改它们，裁掉的部分裁回来时关键帧还在。切割后两半都保留全部关键帧。

没有 `time.speed` 时，时钟的读数就是素材里的时间，`offset` 就是从素材的哪里开始。有 `time.speed` 时，素材里的时间是速度从时钟 0 到当前读数的累积。

同一条轨道上的片段不重叠。命令默认拒绝重叠，也可以要求覆盖，这时被盖住的部分会被裁掉或删除。多人同时修改时仍然可能产生重叠，这不算文件错误，开始得晚的片段显示在上面。

时间轴的长度是所有段落时长之和。片段放到结尾之后时，最后一个段落会自动变长。

其他字段：

| 字段 | 含义 |
| --- | --- |
| `loop` | 素材放完后重复，直到片段结束 |
| `enter`、`exit` | 入转场和出转场，比如淡入、淡出，见[转场](#转场) |
| `hidden` | 不显示。版本可以单独改变它 |
| `draft` | 样片，只用来看想法，不进成片 |
| `link` | `link` 相同的片段一起移动，比如视频的画面和声音 |
| `sectionFit` | 段落变长时：`stretch` 按比例伸缩，`hold` 末尾定格，`span` 跨段落连续 |
| `effects` | 效果，按顺序作用在片段的画面上，见[效果](#效果) |

### 片段的来源

| `kind` | 字段 | 内容 |
| --- | --- | --- |
| `video`、`image`、`audio` | `media` | 素材文件 |
| `scene` | `scene`，或 `library` 加 `resource` | 项目或库里的场景 |
| `sound` | `sound`，或 `library` 加 `resource`，可选 `output` | 代码生成的声音 |
| `music` | `music` | 音符形式的音乐 |
| `timeline` | `timeline` | 嵌套的时间轴，跟随外层的语言和画幅 |
| `color` | `color` | 纯色 |
| `caption` | `text`，可选 `words` | 字幕。`words` 给每个词一个时刻，用于逐字歌词 |

`media` 是 `{ "asset": "<id>" }`，或者库里的文件 `{ "library": "<id>", "path": "…" }`。文字可以直接写，也可以是字符串表的引用 `{ "string": "<键>" }`。

### 转场

转场是在一小段时间里从一边换到另一边，用户只调时长和速度曲线。淡入淡出也是转场，只是另一边“什么都没有”。“没有”是透明：淡入时露出下面的轨道，下面什么都没有就露出时间轴的背景色。

| 类别 | 存在哪 | 时间范围 | 从哪边到哪边 |
| --- | --- | --- | --- |
| 入转场 | 片段的 `enter` | 从片段开头起，`duration` 长 | 没有 → 片段 |
| 出转场 | 片段的 `exit` | 到片段结尾为止，`duration` 长 | 片段 → 没有 |
| 衔接转场 | 轨道的 `joins` | 剪切点附近，由 `align` 决定 | 前一个片段 → 后一个片段 |

```json
{
  "id": "clip_title",
  "start": "0",
  "duration": "5",
  "source": { "kind": "scene", "scene": "title" },
  "enter": { "type": "fade", "duration": "0.5" },
  "exit": { "type": "push", "variant": "left", "duration": "0.4", "curve": [0.42, 0, 0.58, 1] }
}
```

```json
"joins": [
  { "id": "join_1", "from": "clip_title", "to": "clip_interview", "type": "fade", "duration": "1" },
  {
    "id": "join_2",
    "from": "clip_interview",
    "to": "clip_card",
    "library": "lib_7f3a",
    "resource": "ink-wipe",
    "variant": "left",
    "duration": "0.8",
    "align": "before"
  }
]
```

| 字段 | 含义 |
| --- | --- |
| `type` | 内置转场的名称，比如 `fade`。插件提供的带点，比如 `plugin.star` |
| `transition` | 项目里 `transitions/<id>/` 的转场 |
| `library`、`resource` | 素材库里的转场 |
| `variant` | 转场有变体时选哪一个，有变体就必须写 |
| `duration` | 时长，精确时间，大于 0 |
| `curve` | 速度曲线，不写是匀速 |
| `from`、`to` | 只有衔接转场有，都必填：前一个片段和后一个片段，在同一条轨道上 |
| `align` | 只有衔接转场有：`center`（默认）剪切点前后各一半，`before` 在剪切点结束，`after` 从剪切点开始 |

`type`、`transition`、`library` 加 `resource` 三选一，和场景来源一样。衔接转场只在视频和音频轨道上，入、出转场在视频、音频和字幕片段上都能写。

入、出转场属于片段：移动、复制和删除片段时跟着走。编辑器修剪片段时，片段比入、出转场加起来还短的话，先缩短被剪那一侧的，再缩短另一侧。切割时前半留下入转场，后半留下出转场，各自缩到放得下。删除片段时，以它为一边的衔接转场一起删掉。

衔接转场属于接缝：两个片段一起移动、仍然首尾相接时跟着走，也跟到别的轨道上。编辑器移动或修剪一边、让两边不再相接时，在同一步里删掉它，命令的结果里说明，撤销能回来；文件和多人同时改造成的分开不删，按下面的“什么时候不生效”处理。切割前一个片段时 `from` 改成后半。片段变短、衔接转场在这个片段里的部分放不下时，编辑器缩短衔接转场，位置不变：居中的两边一起缩短。编辑器放衔接转场、没有写 `align` 时，按两边片段在剪切点外还有多少画面来选：两边都有就居中，只有一边有就放到那一边，让定格的部分最少。

**片段外的画面。** 衔接转场居中或在一侧时，前一个片段要在结尾之后多演一会儿，后一个片段要在开头之前先出来。这部分按各自的片段时钟往外延，就像片段更长一样：

| 内容 | 片段外 |
| --- | --- |
| 视频 | 文件里被剪掉的部分。时钟早于 0 时定格在第一帧，过了文件结尾定格在最后一帧 |
| 场景 | 时钟照常往外走，早于 0 时停在第 0 帧 |
| 图片、纯色 | 和片段里一样 |
| 关键帧 | 按 `before`、`after` 延伸，默认保持 |

衔接转场在剪切点两边的部分分别放进两个片段里：剪切点前的部分不超过前一个片段，剪切点后的部分不超过后一个片段，超出的截短，进度在截短后的这段时间上从 0 走到 1。

**速度曲线。** `curve` 是四个数 `[x1, y1, x2, y2]`，和 CSS 的 `cubic-bezier()` 同一个意思：x 在 0 到 1 之内，y 在 −10 到 10 之内。

```
进度 = curve((时刻 − 转场开始) ÷ 时长)
```

进度从 0 走到 1，曲线在这段时间上，拖长、缩短转场时形状不变。编辑器的预设是缓入 `[0.42, 0, 1, 1]`、缓出 `[0, 0, 0.58, 1]`、缓入缓出 `[0.42, 0, 0.58, 1]`，和 CSS 的同名曲线相同，项目里存的永远是数字。y 超出 0 到 1 时，允许回弹的转场（`push`）照用，其他的截到 0 到 1。

**内置转场。** 画面和声音各有一套，名称就是 `type`：

| `type` | 变体 | 入转场 | 出转场 | 衔接转场 |
| --- | --- | --- | --- | --- |
| `fade`（画面） | | 淡入 | 淡出 | 叠化 |
| `dip` | `black`、`white` | 从纯色淡入 | 淡出到纯色 | 闪黑、闪白 |
| `wipe` | `left`、`right`、`up`、`down` | 擦入 | 擦出 | 擦除 |
| `push` | 同上 | 推入 | 推出 | 推移 |
| `fade`（声音） | | 淡入 | 淡出 | 交叉淡化，等功率 |
| `fade-linear`（只有声音） | | 线性淡入 | 线性淡出 | 等增益 |

- 变体名是画面运动的方向：`push` 的 `right` 是画面往右走，用作入转场是从左推入，用作出转场是向右推出。`wipe` 的 `left` 是边往左走，用作入转场是从右擦入。
- 画面的转场作用在图层画面上：片段放进片段框、变换和不透明度之后的整幅画面，没有内容的地方是透明的。入转场的前一边和出转场的后一边是“没有”，全透明。颜色都是预乘透明度的。下面 p 是进度，A 是前一边，B 是后一边，混合是 `A × (1 − p) + B × p` 这样逐个像素把预乘的颜色和透明度相加：
  - `fade`：A × (1 − p) + B × p。两边同一个位置都不透明时，中间仍然不透明。入转场就是 B × p，出转场是 A × (1 − p)。
  - `dip`：纯色铺满整个画面，是不透明的。入转场是纯色 × (1 − p) + B × p，出转场是 A × (1 − p) + 纯色 × p；衔接转场前一半是 A × (1 − 2p) + 纯色 × 2p，后一半是纯色 × (2 − 2p) + B × (2p − 1)，正中那一刻只有纯色，盖住下面的轨道。`black` 是 `#000000`，`white` 是 `#ffffff`。
  - `wipe`：一条边沿变体的方向扫过画面，扫过的地方是 B，还没扫到的是 A，边是宽为画面短边 2% 的柔边，柔边里按位置线性混合。边从画面外刚好碰不到画面的地方出发，走到另一侧刚好离开画面，所以 p 为 0 时全是 A，为 1 时全是 B。沿运动方向量，画面长 L、柔边宽 s 时，离出发的那一侧 u 处 B 的份量是 clamp((p × (L + s) − u) ÷ s, 0, 1)。
  - `push`：A 沿变体的方向移动 p 个画面的宽（上下推移是高），B 跟在它后面，离自己的位置还差 1 − p 个画面。两边的画面相加，接缝处不留线。p 超出 0 到 1 时照样移动，就是回弹。
- 入、出转场先作用在各自片段的图层画面上，再进衔接转场：衔接转场拿到的两边，是已经算过入、出转场的画面。同一个片段的入、出转场重叠时，先算入转场，再把它的结果交给出转场。衔接转场重叠时（片段比两头的衔接转场加起来还短），按片段的先后连起来依次算，后一个的前一边就是前一个的结果，和它们从哪一刻开始、ID 是什么无关。
- 衔接转场的结果按正常模式合成到下面的轨道上。
- 默认时长：画面 0.5 秒，声音 0.2 秒。

编辑器画转场时要多用一些内存：转场用到的画面各画在一块和画出来的画面一样大的画布上，每块 1080p 约 8.3 MB，4K 约 33.2 MB。只有淡入淡出时不用；叠化用一块，背景是黑色、下面没有别的东西时一块也不用。一帧里同时用着的最多三块，用完马上给下一个转场用；擦除另外只多用柔边那一条。用过的画布留给后面的帧，连续 300 帧没用到才释放，所以留着的是最近用过的：合成器的最多两块，加上每种转场的代码各一块。按最坏的组合算：同一条轨道上的转场错开时（编辑器会让它们错开），最多留五块（合成器两块，闪黑闪白、擦除、推移各一块），1080p 约 41 MB，4K 约 166 MB；文件里同一条轨道上的转场同时进行时，同一种代码最多要三块（叠化两块），最多留十三块，1080p 约 108 MB，4K 约 431 MB。

**什么时候不生效。** 手写文件、AI 改文件和多人同时改都可能产生下面的情况，编辑器自己的命令只会产生隐藏片段这一种。除了它，这些都列入问题，原样保留，由用户或 AI 修好或删除：

| 情况 | 结果 |
| --- | --- |
| 衔接转场的两边不在这条轨道上、不相邻（`from` 的结尾不正好是 `to` 的开头），或者是同一个片段 | 不生效 |
| 衔接转场的一边被隐藏 | 不生效，就像没有它，两边片段的入、出转场照常生效。隐藏是有意的，不算问题 |
| 同一个剪切点上有两个衔接转场 | ID 排在前面的生效 |
| 片段的同一端既有衔接转场，又有入或出转场 | 衔接转场生效 |
| 入或出转场比片段长 | 截短到片段的长度，进度照样从 0 走到 1 |
| 衔接转场比两边的片段放得下的长 | 剪切点两边的部分各自截短到放得下，进度照样从 0 走到 1 |
| 找不到实现：名称写错、插件没装、变体写错或没写，或者用在不能用的地方 | 预览按 `fade` 显示，导出停在这里 |

这一版的编辑器做画面的全部内置转场，入、出和衔接都有。声音的转场写法已经定下，读写都保留，但还听不到：导出的文件要和项目说的一样，所以这些地方导出停下并说明，不悄悄换成没有转场的声音。找不到实现的画面转场预览按 `fade` 显示，导出同样停下。复制片段时入、出转场原样带上，放不下时按修剪的规则缩短。项目里的转场和素材库里的转场以后实现。

格式上线前的项目可能还有片段的 `fadeIn`、`fadeOut` 和轨道的 `transitions`。它们已经从格式里去掉，读到时丢弃，不算错误，写文件时不再写。打开项目时不提；导入文件夹、在编辑器外改了时间轴文件时，问题里提一句“旧的淡入淡出写法已不支持，被忽略”。

### 效果

效果加工一个片段的画面，比如调色、模糊、裁切。片段的 `effects` 是一个列表，按顺序作用：第一个拿到片段的画面，后一个拿到前一个的结果。

```json
{
  "id": "clip_interview",
  "effects": [
    { "id": "fx_crop", "type": "crop" },
    { "id": "fx_blur", "type": "blur", "enabled": false }
  ],
  "properties": {
    "effect.fx_crop.left": 0.1,
    "effect.fx_blur.radius": { "keys": [{ "time": "0", "value": 0 }, { "time": "1", "value": 12 }] }
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `id` | 在这个片段的效果里唯一 |
| `type` | 内置效果的名称；插件提供的带点。项目和素材库里的效果以后用 `effect`、`library` 加 `resource` 引用 |
| `enabled` | `false` 时不起作用，位置和参数都留着。不写是开 |

**参数是片段的属性。** 效果的参数存在片段的 `properties` 里，路径是 `effect.<效果 ID>.<参数>`，和其他属性一样能打关键帧，关键帧的时间是片段时钟的读数。没写的参数用默认值，内置效果的默认值都让它不起作用。删掉一个效果时编辑器连同它的参数一起删；手写文件里没有效果认领的参数原样保留，不起作用。值超出参数的范围时按边界算，类型不对时按默认值算，都列入问题。

**在合成顺序里的位置。**

```
片段内容放进片段框 → 效果（按顺序）→ 变换、不透明度 → 入转场、出转场 → 混合模式合到下面
```

效果在片段框里做：输入是片段框里的画面（框里没有内容的地方是透明的），大小是片段框在成片上的像素大小，世界单位按这个大小换算。所以片段缩小时模糊跟着变小，旋转不影响效果。片段框比成片大很多时，效果拿到的画面最多是成片像素的四倍、每边最多 8192 像素，看起来一样，只是粗一些。画面全程是预乘透明度的。

**内置效果。** 预览和导出用同一份代码，在合成器里直接运行。

| `type` | 参数 | 做什么 |
| --- | --- | --- |
| `brightness` 亮度 | `brightness`，-1 到 1，默认 0 | 颜色乘 1 + `brightness`，和 CSS 的 `brightness()` 相同 |
| `contrast` 对比度 | `contrast`，-1 到 3，默认 0 | 和 CSS 的 `contrast(1 + contrast)` 相同：-1 是一片中灰 |
| `saturation` 饱和度 | `saturation`，-1 到 3，默认 0 | 和 CSS 的 `saturate(1 + saturation)` 相同：-1 是灰度 |
| `temperature` 色温 | `temperature`、`tint`，-1 到 1，默认 0 | 每个颜色通道乘一个系数：t = 0.25 · temperature，m = 0.25 · tint，红 1 + t + m/2，绿 1 − m，蓝 1 − t + m/2，不超过覆盖度。正的色温偏暖，正的色调偏品红 |
| `blur` 模糊 | `radius`，世界单位，不小于 0，默认 0 | 高斯模糊，标准差是 `radius`，和 CSS 的 `blur()` 相同。框外是透明，所以框的边也变柔 |
| `crop` 裁切 | `left`、`top`、`right`、`bottom`，片段框的比例，0 到 1，默认 0 | 去掉框的四边，变成透明。框的大小不变，留下的部分位置不变；两边相遇时什么都不剩 |

不透明度和混合模式是片段的属性（`opacity`、`blend`），不是效果。

**找不到实现时。** 名称写错、插件没装，或者用在声音片段上：预览里跳过这个效果，导出停在这个片段上，列入问题。这一版只有画面片段能加效果。

格式上线前的项目可能还有片段的 `crop.left`、`crop.top`、`crop.right`、`crop.bottom` 属性，以及效果里的 `properties`。它们已经去掉（裁切是效果了，参数是片段的属性），读到时丢弃，不算错误。轨道、总线和主输出的声音效果也一样：参数是它们 `properties` 里的 `effect.<效果 ID>.<参数>`。

### 属性和关键帧

所有能动的东西都是属性，放在 `properties` 里。一个属性是一个值，或者一组关键帧：

```json
{
  "properties": {
    "param.size": 64,
    "opacity": {
      "keys": [
        { "time": "0", "value": 0, "interp": "bezier", "out": [0.42, 0] },
        { "time": "1/3", "value": 1, "in": [0.58, 1] }
      ],
      "after": "hold"
    }
  }
}
```

关键帧的时间是片段时钟的读数，见上一节。`interp` 是 `linear`、`bezier`、`hold`、`spring` 或 `preset`，描述到下一个关键帧的变化。`before` 和 `after` 是前后的延伸方式：`hold`、`loop`、`pingpong`、`continue`。`modifiers` 目前有带种子的 `noise`，种子是必填的，这样渲染结果可以重复。

`spring`、`preset` 和 `noise` 的字段已经定下，效果之后实现。在那之前 `spring` 和 `preset` 按线性算，`noise` 不生效。`noise` 的 `amount` 和属性同一个单位。

内置属性：

| 属性 | 含义 |
| --- | --- |
| `transform.x`、`transform.y` | 锚点在世界里的位置，世界单位，默认 0 |
| `transform.width`、`transform.height` | 片段框的大小，世界单位，不能小于 0，默认不写 |
| `transform.anchorX`、`transform.anchorY` | 锚点，片段框的比例，默认 0.5 |
| `transform.scale` | 框和内容一起缩放，默认 1 |
| `transform.rotation` | 旋转，度，顺时针为正，不折返，720 是两圈 |
| `opacity` | 不透明度，0 到 1，默认 1。入、出转场在它之后再算，所以淡入淡出不占用它 |
| `fit` | 素材怎么放进片段框：`contain`（默认）、`cover`、`fixed`。不能打关键帧，手写的文件里有关键帧时只用第一个的值，并列入问题 |
| `blend` | 混合模式，片段的画面怎么合到下面的轨道上：`normal`（默认）、`multiply` 正片叠底、`screen` 滤色、`overlay` 叠加、`darken` 变暗、`lighten` 变亮、`add` 相加（颜色和覆盖度都相加）。和 Canvas 2D 的同名合成方式相同。在入、出转场之后算；衔接转场的结果两边的混合模式相同时用那一种，否则按 `normal` |
| `time.speed` | 播放速度。打关键帧就是变速 |
| `audio.volume` | 音量，分贝，0 是原音量 |
| `audio.pan` | 声像，-1 到 1 |
| `audio.pitch`、`audio.preservePitch` | 移调（半音）、变速时保持音高 |

其他属性来自片段的内容和效果：`effect.<效果 ID>.<参数>` 是片段上一个效果的参数，见[效果](#效果)；`param.<ID>` 是场景参数，`object.<对象>.<属性>` 是代码登记的对象，`object.<骨架>.<骨骼>.<属性>` 是对象里的子对象，段数不限，`element.<ID>.<属性>` 是 HTML 和 SVG 元素，`caption.<名称>` 是字幕样式。场景里的这些属性怎么用，见[场景运行时](scene-runtime.md#可以打关键帧的对象)。

元素的属性是固定的：`x`、`y`（相对元素原来的位置，世界单位）、`scale`、`rotation`（度）、`opacity`，HTML 元素还有 `blur`（世界单位）、`color`、`background`，SVG 元素还有 `fill`、`stroke`。颜色写成 `#rrggbb` 或 `#rrggbbaa`。

代码对象的属性由代码登记，项目里不记它们的类型。登记的类型和存的值对不上时，这个属性不起作用，用登记的默认值，项目里的值原样保留。没有对象认领的属性也原样保留，编辑器不会自己删除或改写它们。

属性路径就是存储的键，所以里面只有稳定的 ID，没有显示名称，也没有层级：改名和换父级都不改路径。每一段只能用 ID 的字符，不能是 `constructor` 或 `prototype`。

### 曲线怎么求值

求值分两步：先算出 0 到 1 的进度，再按值的类型混合。所以缓动和值的类型无关。

- 片段时钟的读数是 `offset + (时刻 − start)`。
- `interp` 不写是 `linear`，描述到下一个关键帧的变化，最后一个关键帧上的 `interp` 没有作用。
- 贝塞尔和 CSS 的 `cubic-bezier` 相同：`(x1, y1)` 是这个关键帧的 `out`，`(x2, y2)` 是下一个关键帧的 `in`。x 在 0 到 1 之内，y 不限。没写 `in` 是 `(1, 1)`。
- `tangent` 只告诉编辑器以后怎么改手柄。求值只看 `in` 和 `out`。`auto` 的关键帧，编辑器在下次改这条属性时会重算它贝塞尔一侧的手柄，写进去的 `in`、`out` 会被换掉；要固定手柄，写 `aligned` 或 `broken`。`tangent` 不改 `interp`：保持和线性的关键帧还是保持和线性。向量和数字列表的各分量共用一组手柄：`auto` 先按每个分量单独算出手柄，再按各分量在这一段的变化量加权平均，不变的分量不算，所以只有一个分量在变时和数字一样，每个分量都不会越过前后的关键帧。
- `before`、`after` 不写是 `hold`。`loop` 和 `pingpong` 的周期是第一个到最后一个关键帧。`continue` 按端点的斜率延伸，只对数字有效，其他类型按 `hold`。
- `loop` 的边界：时刻落在最后一个关键帧上时取它的值，紧接着从第一个关键帧重新开始，所以之后每个周期的边界取第一个关键帧的值，不是最后一个。关键帧 `1` 和 `3` 的值是 10 和 30 时，`after: loop` 在 3 是 30，在 3 之后马上回到 10 附近，在 5 和 7 是 10。`before: loop` 对称：往前走时，第一个关键帧上取它的值，紧接着接上最后一个关键帧，所以周期边界同样取第一个关键帧的值。`pingpong` 在边界上连续，没有这个跳变。
- 值的类型不能插值时，整段保持，忽略 `interp`。数字线性混合。角度也是线性，不走最短路径，这样能转多圈。
- 颜色写成 `#rrggbb` 或 `#rrggbbaa`，在 Oklab 空间线性混合，透明度也线性，颜色按透明度加权，和 CSS 的 `color-mix` 一样：完全透明的一端不带进自己的颜色。混合出来不透明时写成 `#rrggbb`。
- 向量（`vec2`、`vec3`、`vec4`）和数字列表（`numbers`）逐个数字线性混合，全部分量共用一组关键帧和缓动。两个列表长度不同时整段保持。`continue` 对它们按 `hold`。
- 只有一个关键帧时是常量。
- 比较时刻有 1e-9 秒的容差，正好落在帧上的 `hold` 关键帧不会早一帧或晚一帧。
- `modifiers` 在延伸之后叠加。

### 世界坐标

画面上的位置是世界里的位置，摄像机决定看到世界的哪一部分。这样不同分辨率、不同画幅的时间轴用同样的数据，方形在哪个画幅里都是方形。

| 项 | 约定 |
| --- | --- |
| 原点 | 舞台中心 |
| 方向 | x 向右，y 向下，旋转顺时针为正 |
| 单位 | 世界单位，舞台的短边是 1080。这是格式常量，不是项目设置 |
| 场景里 | 1 世界单位是 1 CSS 像素 |

舞台是画幅按短边 1080 换算的大小。两个方向用同一个比例，所以任何画幅都不变形：

```
k = 1080 / min(format.width, format.height)
舞台 = (format.width × k, format.height × k)
成片像素 = 世界坐标 ÷ k + 成片中心
```

1920×1080 和 3840×2160 的舞台都是 1920×1080，1080×1920 的舞台是 1080×1920。一个 200×200 的方块在 4K 成片里边长是 400 像素。

摄像机之后实现。在那之前摄像机静止：位置 0，0，取景范围就是舞台。

### 片段框

每个有画面的片段是世界里的一个矩形，叫片段框。框由属性决定，素材怎么放进框由 `fit` 决定。

| 写了什么 | 片段框 |
| --- | --- |
| 宽高都没写，`fit` 是 `contain` 或 `cover` | 等于舞台，换画幅时自动跟着变 |
| 宽高都没写，`fit` 是 `fixed` | 素材原始大小，1 素材像素是 1 单位 |
| 只写一个 | 另一个按素材的宽高比算。纯色没有宽高比，用舞台的 |
| 都写 | 就是这个框 |

| `fit` | 素材怎么放进框 |
| --- | --- |
| `contain` | 完整显示，保持比例 |
| `cover` | 铺满，保持比例，超出框的部分裁掉 |
| `fixed` | 铺满框，不保持比例。框默认就是素材原始大小，所以不写宽高时不变形 |

纯色铺满片段框，`fit` 对它没有作用。框跟的是舞台，不是摄像机，否则摄像机推近时画面不会放大。

变换的顺序是固定的：

```
框内的点 → 减去锚点 → 缩放 → 旋转 → 加上 x、y → 世界坐标
```

缩放片段时改 `transform.scale`，不改宽高，这样片段继续跟随舞台。宽高只在要固定大小时才写。

## 差异

版本不是副本，而是母版加差异。差异文件放在 `timelines/<id>/overrides/`，文件名由范围决定：

| 文件 | 范围 |
| --- | --- |
| `language.en.json` | 一种语言 |
| `format.vertical.json` | 一种画幅 |
| `version.en.vertical.json` | 一个版本 |

```json
{
  "scope": { "language": "en" },
  "sections": { "section_body": { "duration": { "value": "26", "base": "20" } } },
  "clips": {
    "clip_title": { "properties": { "param.size": { "value": 48, "base": 64 } } }
  }
}
```

`value` 是这个范围的值，`base` 是记录差异时母版的值。母版后来变了，就能发现这个差异要确认。差异按整个属性覆盖，包括它的全部关键帧。

取值顺序是：版本、画幅、语言、母版，找到就停。

差异只能改已有的对象，不能增加。只在某个版本出现的片段，在母版里设 `hidden`，再在差异里取消。

## 场景和声音

```json
{
  "name": "标题卡",
  "entry": "index.html",
  "runtime": 1,
  "params": [{ "id": "size", "name": "字号", "type": "number", "default": 64, "min": 12, "max": 200 }]
}
```

场景的文件夹里是真实的代码，`entry` 是入口，要是 `.html`、`.js` 或 `.mjs` 文件。代码直接运行，不经过编译，所以用 JavaScript，不用 TypeScript。`runtime` 是这段代码面向的运行时接口版本，现在是 1，内容见[场景运行时](scene-runtime.md)。新版编辑器会继续支持旧接口，所以旧项目的渲染结果不变。写给更新版本的场景不运行，列入问题。

场景的文件夹只放文本。图片、字体这些放进 `assets.json`，代码里用 `aq.asset(id)` 取。

参数的 `type` 是 `text`、`number`、`color`、`boolean`、`choice` 或 `asset`。片段用 `param.<id>` 赋值，也可以打关键帧。参数的 `id` 要能写进属性路径，只用英文字母、数字、下划线和连字符，否则片段不能给它赋值。差异可以覆盖片段的任何属性，场景文件本身不能差异化。

声音和场景一样，放在 `sounds/`，代码生成音频。`outputs` 列出一段程序能产生的多个声音，片段用 `source.output` 选一个。入口要是 `.js` 或 `.mjs` 文件，代码能用什么见[场景运行时](scene-runtime.md#声音)。

```json
{
  "name": "提示音",
  "entry": "sound.js",
  "runtime": 1,
  "params": [
    { "id": "duration", "name": "时长", "type": "number", "default": 1.5, "min": 0.05, "max": 300 },
    { "id": "seed", "name": "种子", "type": "number", "default": 1 }
  ]
}
```

片段用 `param.<id>` 赋值，代码拿到的是片段的值，没有时是 `default`。声音的结果只由这些决定，所以有两个参数是有固定含义的：

| 参数 | 含义 |
| --- | --- |
| `param.duration` | 声音有多长，秒，最长 300 |
| `param.seed` | 随机数的种子。代码里的 `Math.random` 也来自它。没有时用声音 ID 算出的固定值 |

裁剪和切割片段只是露出声音的一部分，不改变声音，所以时长不跟着片段走，片段也不能拉得比时长更长。编辑器放声音时总会写下时长。手写的片段没有 `param.duration` 时，声音的长度是片段时钟结束时的读数，这时裁剪和切割会重新生成，切开的前一半是另一个声音。

参数打了关键帧时只用第一个的值。

场景和声音的代码可以共用 `code/` 里的模块。场景和声音都在沙箱里运行，不能联网。

## 素材

```json
{
  "assets": {
    "interview": {
      "kind": "video",
      "path": "assets/interview.mp4",
      "storage": "lfs",
      "hash": "sha256-…",
      "info": { "duration": "12.5", "width": 1920, "height": 1080 }
    }
  }
}
```

片段通过 ID 引用素材，所以文件改名不会断。`storage` 说明文件在哪：`git` 和 `lfs` 随仓库走，`local` 只在一台电脑上，`remote` 在用户的对象存储里（要写 `url`）。`license` 和 `credit` 用来导出署名清单。`tags` 是给人找东西用的标签，比如 `["片头", "竖屏可用"]`，每个最多 40 个字、不重复、最多 30 个；它们和项目的 `tags` 不同，不锁定任何东西。场景和声音的 `scene.json`、`sound.json` 也可以写 `tags`。

`hash` 是文件内容的 SHA-256，写成 `sha256-` 加 URL 安全的 base64，带末尾的 `=`。别的工具写成普通 base64 或十六进制也能读。

项目是电脑上的一个文件夹时，素材文件就在这个文件夹里，编辑器按 `path` 读，不复制进浏览器。从别处拿进来的文件复制进 `assets/`，用原来的文件名（换掉系统不允许的字符，重名时加编号），写完才加进 `assets.json`；本来就在项目文件夹里的文件直接用它所在的路径。文件的内容和 `hash` 对不上（在外面被换过）或者文件不见了，编辑器列为问题，由人决定用新文件还是改成新的位置。

## 字符串表

```json
{
  "strings": {
    "intro.title": { "text": "What is an atom", "base": "原子是什么" }
  }
}
```

`base` 是翻译时母版的文字。它和现在的母版不同时，这条翻译要更新。

## 库

`libraries.json` 声明依赖，`libraries.lock.json` 固定具体存档，这样库更新不会悄悄改变已有的成片。

## 批注

`notes.json` 保存批注，跟项目一起存档，不进成片。

## 校验和问题

校验分两层：

- **错误：** 文件不符合格式，这个文件不能用。其他文件不受影响。没有可用的 `animaquill.json` 时项目打不开。
- **问题：** 引用的东西不存在，比如素材没了、库没关联、翻译缺失、差异指向已删除的片段。项目照常打开，问题列出来等人处理。

读不出来的文件不会被写回，所以不会用空内容覆盖还能修的文件。

## 导出和导入

项目在浏览器里时，可以导出成这样一个文件夹，也可以从这样的文件夹导入，用来备份和搬家。

导出写入全部文档和 `scenes/`、`sounds/`、`code/` 里的文件，再把 `assets.json` 列出的素材文件放到各自的 `path`。

- 总是写进一个新的文件夹，同名的文件夹已经存在时加上编号，不改动已有的内容。
- `animaquill.json` 最后写入。写入期间文件夹里有 `导出未完成.txt`，全部写完才删除。所以中途停下的文件夹不是项目，这个文件也说明了情况。
- 文件夹名来自项目名。浏览器不允许的字符会被去掉或替换，比如首尾的 `~` 和看不见的字符。
- 浏览器不允许写进文件夹的文件名（比如 `aux.js`、`~草稿.html`）和路径相同的文件不写入，列出来，其余的照常写完。
- 不能写入文件夹的浏览器导出成一个 zip 文件，里面是这个文件夹，文件不压缩。解压后再导入。zip 里没有文件名的限制。

导入总是产生一个新项目，已有的项目不受影响。

- `id` 已经有项目在用时，导入成副本，换一个新的 `id`。
- `animaquill.json` 不能用时整个文件夹不导入，并列出错误。`formatVersion` 比编辑器新时也拒绝，有 `导出未完成.txt` 时也拒绝。
- 别的文档有错误时，和打开项目一样只损失这个文档，但导入前要先问：列出会丢的内容和原因，用户选择跳过才继续，默认是取消。新项目缺一块却看起来完整，用户可能就把原来的文件夹删了。
- `animaquill.json` 列出的时间轴损坏或者不在文件夹里时，导入成一条空的时间轴，指向它的内容不会失效。列表之外的时间轴损坏时不带入。场景和声音的描述文件损坏时，它们的代码文件照常带入。
- 选中的文件夹没有 `animaquill.json`，但里面正好有一个项目文件夹时，导入那一个。
- 素材文件不在文件夹里时，条目照常保留，列出来。文件内容和 `hash` 不一致时，不带入这个文件，同样列出来。没写 `hash` 的素材，导入时算出来写上。
- `scenes/`、`sounds/`、`code/` 里的文本文件原样带入。不是 UTF-8 文本的文件、超过 32 MiB 的文件和格式之外的文件（比如 `README.md`）不带入，列出来。原来的文件夹不会被改动，所以它们还在那里。超过 32 MiB 的文件在导出时也会提醒。文档没有大小限制。
- 不读 `.git`、`.animaquill` 和 `node_modules`。
- 浏览器看不到符号链接。链接本身带不进来，Chrome 还会漏掉文件夹里被链接指向的子文件夹。素材、时间轴和场景的入口文件缺了会列出来，`code/` 里的文件没有办法发现。

## 版本和迁移

`formatVersion` 是整个项目的格式版本。任何格式改动都会提高版本号，并提供迁移：

- 打开旧版本项目时先升级，升级不改原文件，由用户确认后才写入。
- 新格式的项目不能用旧版编辑器打开，避免丢掉旧版不认识的内容。

浏览器里保存的项目是 Yjs 文档，它的存法不属于文件格式，但也会随编辑器改变，比如差异和字符串表改成逐条存放。改了之后，旧文档照常打开；更新前就开着的页面要刷新，否则它写入的内容新页面可能看不到。

`packages/schema/fixtures/` 保留了每个版本的示例项目，从不修改，自动测试保证它们一直能打开。
